## Proposal — **P-W26-CASHFIT (Ring 2)**

> **Note on draft policy.** This proposal is **deterministic and mandate-derived** — it codifies an existing implicit fallback into an explicit rule with logged decision options. No TradingView backtest is required because no parameter is being tuned and no edge is being introduced — the change reduces ambiguity in an existing corner case that has fired 5 times across the live window. Drafting this without TV evidence is consistent with the W25 §Proposal item 4 framing ("the cash-fit pre-check is the most proposable W25 candidate — it is deterministic (no backtest needed, pure mandate-derived mechanical constraint)") and does **not** require user pre-authorization of the W20 paper-paper-evidence escalation. If the user disagrees with this drafting policy, replying `[N]` rejects the proposal and the rule does not apply — no behavior change either way (the implicit fallback continues as it has).

### Change

Add a new entry-rule sub-step **8a** to `strategy.md`, immediately following rule 8 (one entry per wake):

```
8a. **(W26-CASHFIT) Cash-fit pre-check + rule-8 fallback.** Before opening a position, compute
    required_notional = size × fill_price (where size is the strategy-mandated 1.5%-risk sizing).
    If required_notional > available_cash:
      (i)  Log REJECT with reason `cash-insufficient`, required_notional, available_cash, shortfall.
      (ii) Advance to the next rule-8 eligible candidate (next 30d-rank-desc among rules 1+2+2a+3+4a+5+5a passers,
           respecting cluster cap 6a, position cap 6, risk cap 7, and 5b cooldowns).
      (iii) Re-run the cash-fit check on that candidate. Repeat (i)-(ii) until either a candidate passes or
            the eligible-pool is exhausted.
      (iv) If pool exhausted, log SKIP-WAKE with reason `all-rule-8-candidates-cash-insufficient` and
           take no entry this wake.

    This rule does NOT modify sizing (which remains 1.5% × equity / stop-distance per strategy.md), does
    NOT allow leverage or margin (mandate forbids), and does NOT permit partial fills. It only governs
    *which* eligible candidate gets the wake's one entry slot.
```

### Rationale

1. **5 cash-binding instances** across W24/W25/W26 demonstrates recurrence (3+ threshold from W25 §Proposal met).
2. **Mandate-derived constraint** — leverage is forbidden by guardrails.md, so notional > cash is structurally impossible to honor at the mandated 1.5% sizing. The current implicit behavior (W26: skip the rejected rank, W25: fall back to next-eligible, W24: degrade-to-cash partial sizing) is inconsistent — three different handlings of the same situation.
3. **Logging codification, not behavior change.** The proposed rule formalizes the fallback that 4 of 5 instances effectively used (rule-8 fallback or implicit skip). The single instance that did NOT use this pattern (W24 BTC, which used degrade-to-cash partial sizing at 0.72% risk) was a discretionary deviation — the proposal would have it follow the consistent pattern (REJECT + fallback) instead.
4. **No backtest required** — the rule does not introduce any edge or parameter. It chooses *which* of the already-eligible candidates is filled when the strategy-mandated size cannot be funded by cash. The trade-set quality is identical; only the candidate-selection ordering changes in the cash-binding corner case.
5. **Audit trail improvement.** Today's routine-03 had to invoke an external memory lesson reference to explain the SUI/LTC/AVAX rejections — those decisions should be a direct consequence of an explicit rule, not an implicit pattern that requires lesson-file context to interpret.

### Risk

- **Low.** The rule is a *fallback-resolution* codification, not an edge-introduction. The eligible-candidate set is unchanged (same rules 1+2+2a+3+4a+5+5a+6a+7 govern eligibility); only ordering within that set changes when cash binds.
- **Slight behavior shift on W24-type cases:** the W24 BTC entry that ran at 0.72% risk (degrade-to-cash) would now REJECT and fall back to next-eligible. That outcome is preferable — degrade-to-cash sizing makes risk-per-trade non-deterministic and harder to reconcile with the 1.5% target. The W24 BTC trade closed at −0.60R (−$47.27); under the new rule that BTC entry would not have been taken and the next-eligible candidate would have been considered. Counterfactual: SOL was eligible the same wake at full 1.5% sizing — taking SOL instead would have caught the same general direction with a clean risk profile. Not a guaranteed improvement in any single instance, but a structural improvement in risk-determinism.

### Expected impact

- **No expected change to win rate or average R per trade** — the candidate-set quality is unchanged.
- **Risk-per-trade becomes consistently 1.5%** instead of occasionally degrading to 0.5–1.0% on cash-bound top-rank entries.
- **Wake-skip frequency may increase** marginally on multi-position-open wakes where all eligible candidates are top-cap pairs with notionals > cash. Empirically (5 instances in 68 live days), the binding rate is ~1 wake per 14 days; the proposed rule reduces, not increases, behavior ambiguity in those wakes.
- **Audit clarity improves** — every cash-binding decision becomes a logged explicit rule consequence.
